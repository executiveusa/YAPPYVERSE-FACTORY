# YAPPYVERSE NORTH STAR

## Governing goal

**Yappyverse is successful when the owner can direct outcomes instead of managing tasks, while an owned network of agents reliably turns ideas, client needs, and intellectual property into verified media, software, campaigns, and revenue.**

This is the governing objective for architecture, prioritization, automation, and product decisions.

## Definition of success

Yappyverse v1 is successful when all of the following are true:

1. The owner states an outcome once; the system decomposes, routes, monitors, recovers, and reports without manual prompt shuttling.
2. Hermes/Governor maintains goals, active work, dependencies, costs, deadlines, evidence, and exception reporting.
3. Every substantive work item is tracked in Beads with an owner, status, dependencies, acceptance proof, and receipts.
4. Characters are durable entities with canonical identity/config, references, model/mesh, textures, rig, animation, voice, personality, provenance/rights, and usage history.
5. The media factory can run end-to-end: source/transcript -> story architecture -> script/edit brief -> production -> QA -> approval -> publish -> verify -> learn.
6. The business factory can run end-to-end: opportunity -> offer -> assets -> distribution -> lead/sale -> fulfillment -> evidence -> case study -> recurring/reusable value.
7. Agent-operable interfaces prefer authoritative CLI/API/MCP paths; browser/computer control is a fallback.
8. Paid work is cost-attributed to project, bead, operation, and outcome.
9. The system learns from verified work without blindly merging upstream changes or corrupting canonical persona/workflows.
10. The system produces measurable commercial or mission outcomes: revenue, client results, audience growth, owned IP, reusable assets, reduced labor, or operating leverage.

## First acceptance milestone

One owner command must produce one complete, verified commercial/media outcome with no manual routing by the owner.

Initial acceptance task:

> "Get ASC3ND's Wednesday 'Why We Started' Reel ready."

Expected autonomous chain:

`campaign context -> source/transcript -> story mining -> series placement -> reel direction -> Opus execution -> taste review -> truth/privacy review -> final review MP4 -> caption/post proposal -> owner approval -> schedule/publish -> live verification -> cost/evidence report`

The owner should intervene only at the taste/publication gate unless an exception, cost anomaly, blocker, or high-consequence decision requires escalation.

## Operating constraints

- Beads is mandatory for all substantive work. See `docs/BEADS_POLICY.md`.
- ICM structures context and stage contracts; Beads tracks durable work and dependencies.
- Builders cannot approve their own output.
- Public claims, publication, irreversible actions, credential/security changes, and material spending remain gated by policy.
- Prefer one verified slice before scaling.
- Preserve owner control, rollback, evidence, and source truth.

## Priority test

Before starting work ask:

> Does this measurably move Yappyverse toward owner-level outcome supervision, verified autonomous execution, or commercial/mission value?

If not, park it in Beads rather than expanding scope.
